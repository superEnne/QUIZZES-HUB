## PART B — Name the Term in a Situation

**37.** A food app asks a payment provider to process money without knowing how that provider works inside. What is it using?
- A. Virus
- B. API
- C. Middleware
- D. Cookie

**38.** A function has the units locked inside it, so it keeps returning the old amount even after the units change. What does this show?
- A. Loose coupling
- B. Interoperability
- C. Tight coupling
- D. Reliability

**39.** A function reads the units from the message handed to it, so it stays correct when the units change. What does this show?
- A. Loose coupling
- B. Tight coupling
- C. Format mismatch
- D. Security

**40.** One system stores an amount in pesos and the other reads it as dollars. What has failed?
- A. Security
- B. Interoperability
- C. Reliability
- D. Coupling

**41.** Three school offices re-type information by hand because their systems cannot share data. What is missing?
- A. Systems integration
- B. Data standardization
- C. Encryption
- D. Middleware

**42.** A school portal shows grades, enrollment, and accounts together on one dashboard. Which level is this?
- A. Data level
- B. Process level
- C. Application level
- D. Presentation level

**43.** A payment company will not hand over its private code, so it offers a safe doorway others can connect to instead. What is the doorway?
- A. Password
- B. API
- C. Database
- D. Backup

**44.** Your system sends out a call for user number one, and the other system sends back JSON. What is this cycle?
- A. Request and response
- B. Hub-and-spoke
- C. Event-driven
- D. Coupling

**45.** HTML, CSS, and JavaScript work together to build one page. What does this already demonstrate?
- A. Integration
- B. Encryption
- C. Standardization
- D. Debugging

**46.** A company keeps adding systems, and the direct wires between them explode into a tangled mess. Which design is this?
- A. Hub-and-spoke
- B. Point-to-point
- C. Middleware
- D. Microservices

**47.** The same company adds one central piece so every system connects there instead of to each other. Which design is this now?
- A. Point-to-point
- B. Microservices
- C. Hub-and-spoke
- D. Event-driven

**48.** An online checkout talks to payment, inventory, and shipping all at once so the user sees one smooth process. What is this?
- A. Data standardization
- B. Systems integration
- C. Tight coupling
- D. Static design

**49.** A store's system reacts the moment an order is placed instead of checking for new orders over and over. What kind of system is it?
- A. Event-driven
- B. Schedule-based
- C. Point-to-point
- D. Static

**50.** A business rents server power online and scales up only during peak season. What is it using?
- A. Middleware
- B. The cloud
- C. A hub
- D. A web service

**51.** System A never talks to System B directly. It hands its message to something in between, which delivers it. What is that something?
- A. Middleware
- B. API
- C. Client
- D. Format

**52.** A restaurant system, a payment app, a mapping service, and a messaging service all work together so an order feels like one smooth app. What is this?
- A. One giant program
- B. Systems integration
- C. A static website
- D. Tight coupling

## PART C — True or False

Write **T** if correct, **F** if wrong. Several are correct statements with one term swapped.

**T1.** A system is a program or application that performs a specific job on its own.
**T2.** Systems integration means building every part of a program from zero.
**T3.** Integration connects parts that already exist so they cooperate.
**T4.** A communication mechanism is the agreed method for one system to send a request and receive a response.
**T5.** When choosing how two systems will communicate, the platform each runs on does not matter.
**T6.** Matching data is easier to pass between systems than mismatched data.
**T7.** Data standardization arranges shared data in a common, agreed format.
**T8.** Systems can throw raw data at each other as long as both are online.
**T9.** A static website changes its content depending on who is looking at it.
**T10.** A dynamic website changes based on the user or the situation.
**T11.** CSS lays out the structure and content, like the skeleton.
**T12.** JavaScript adds the behavior and logic, like the muscles.
**T13.** A dynamic website can be built properly using only one language.
**T14.** An API lets one system request data while the complex work stays hidden.
**T15.** A web service is an API that can be reached over the internet.
**T16.** To use another system's API, you must first understand how it works inside.
**T17.** Interoperability means exchanging information, and exchanging alone is enough.
**T18.** For interoperability, both the format and the meaning must agree.
**T19.** If one system reads an amount as pesos and the other as dollars, interoperability has failed.
**T20.** Coupling is how dependent two systems are on each other.
**T21.** In tight coupling, a change in one system can break the other.
**T22.** Loose coupling means systems depend only on an agreed message.
**T23.** Tight coupling is what we aim for.
**T24.** Loose coupling makes a setup easier to maintain and grow.
**T25.** A message is the agreed shape of the data that systems pass to each other.
**T26.** At the data level, systems share the same database or files.
**T27.** At the presentation level, systems coordinate one full workflow together.
**T28.** At the application level, systems call each other's functions or APIs.
**T29.** Without integration, copies of data drift out of sync.
**T30.** With integration, there is one source of truth.
**T31.** In a well-integrated setup, the user should be able to tell how many systems are working behind the scenes.
**T32.** In point-to-point, every system is wired directly to every other system.
**T33.** Point-to-point stays manageable no matter how many systems you add.
**T34.** In hub-and-spoke, one central hub routes messages between all the systems.
**T35.** Middleware works like a translator and a post office combined.
**T36.** With middleware in place, System A still talks to System B directly.
**T37.** Middleware lets each system change on its own without breaking the other.
**T38.** Microservices are small independent services that each do one job.
**T39.** With the cloud, you pay for what you use and scale when you need to.
**T40.** Event-driven systems constantly check for updates rather than reacting to events.
**T41.** In the request and response cycle, your system acts as the server.
**T42.** The response usually comes back as JSON.
**T43.** Format mismatch happens when one system sends XML while another expects JSON.
**T44.** Reliability asks who is allowed to call a service and how data is protected in transit.
**T45.** Integration evolved from point-to-point wiring toward shared, standard services.
